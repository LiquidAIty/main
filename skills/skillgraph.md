# Reusable Procedures and the Code Wiki Idea

@skill id=skillgraph
@type Skill
@status active

Recovered from `2ddadeeb^` and refreshed September 9, 2026. Use when maintaining proven operating
knowledge or assessing the owner's code-wiki idea. The source of repository procedures is
`skills/*.md`; native Hermes skills and memory retain their separate per-profile ownership.

A useful skill contains a specific purpose, scope, proven procedure, evidence needed to trust
the result, and known traps. It is not a task history, generated report, model autobiography,
or a replacement for current code. Keep examples from becoming universal product requirements.

Restore a lost skill by reading its exact Git version, checking present owners, and refreshing
obsolete references while preserving the useful lesson. Distinguish a recovered procedure from
a newly validated one. Do not claim a skill is runtime-loaded just because its file exists.

Select skills on demand. Saved Card/profile settings control runtime availability; restoring
documents does not attach all skills to Main. Do not ingest procedures as project facts or
automatically turn completed conversations into a skill library.

The old Neo4j SkillGraph importer and an automatic LLM wiki are not current runtime capabilities.
Their restoration is not part of recovering these documents. The code-wiki idea remains a
candidate: it should improve retrieval of relevant, current code knowledge with explicit source
ownership, not accumulate another unreviewable copy. Use existing CBM for repository structure.

See [skillgraph-neo4j-indexing-skill.md](skillgraph-neo4j-indexing-skill.md) for the historical
index boundary, and the publication/retrieval skills for the current procedure. No new graph,
runtime, profile or automatic skill ingestion is introduced by these documents.
